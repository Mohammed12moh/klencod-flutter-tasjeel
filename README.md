# تسجيل (Tasjeel) — تطبيق تسجيل نتائج الورق والدومينو

تطبيق Flutter + Supabase، Dark Mode، RTL بالكامل.

> ⚠️ تنبيه مهم: هذا المشروع كُتب كمصدر كامل جاهز للبناء، لكنه لم يُبنَ فعلياً
> إلى ملف APK هنا، لأن بيئة إنشاء هذا الملف لا تملك Flutter SDK ولا اتصال
> إنترنت لتنزيل الحزم. اتبع الخطوات التالية على جهازك (أو أرسل هذا المجلد
> لي عبر Claude Code الذي يملك بيئة بناء كاملة) لإنتاج الـ APK النهائي.

## الخطوات

### 1. تثبيت المتطلبات
- ثبّت Flutter SDK (قناة stable): https://docs.flutter.dev/get-started/install
- شغّل `flutter doctor` وتأكد أن كل شيء ✅، خصوصاً Android toolchain.

### 2. إنشاء هيكل منصة Android (وiOS إن أردت)
هذا المصدر يحتوي بالفعل على `android/app/src/main/` (AndroidManifest.xml
بنظام embedding v2 الصحيح، MainActivity.kt، الثيمات، خلفية شاشة البدء)،
لكنه لا يحتوي على باقي ملفات Gradle (`gradlew`, `build.gradle`,
`settings.gradle`, ملف wrapper الثنائي) لأنها تُولَّد تلقائياً ولا يمكن
كتابتها يدوياً هنا بأمان. نفّذ داخل مجلد المشروع:

```bash
flutter create . --platforms=android --project-name=tasjeel --org com.tasjeel
```

سيسألك Flutter عن تعارض بعض الملفات الموجودة مسبقاً (AndroidManifest.xml،
MainActivity.kt، styles.xml) — اختر **الإبقاء على نسختك الحالية (overwrite: No)**
لهذه الملفات تحديداً لأنها معدّة مسبقاً بالشكل الصحيح، ووافق على توليد
باقي ملفات Gradle الناقصة بشكل طبيعي.

> ℹ️ إن كنت تبني عبر أداة سحابية مثل Klencod IDE بدل جهازك، وظهر خطأ
> **"Build failed due to use of deleted Android v1 embedding"**: هذا يعني
> أن تلك الأداة ولّدت MainActivity بنظام قديم. استخدم ملف
> `android_v2_embedding_fix.zip` المنفصل المرفق مع هذا الرد لاستبدال
> الملفات المسببة للمشكلة مباشرة داخل مستودعك دون الحاجة لإعادة إنشاء
> المشروع بالكامل — التعليمات داخل `كيفية_الإصلاح.md` في ذلك الملف.

### 4. تركيب أيقونة التطبيق (من الصورة التي أرسلتها)
الصورة محفوظة بالفعل في `assets/images/app_icon.png`. شغّل:

```bash
flutter pub get
flutter pub run flutter_launcher_icons
```

هذا يولّد تلقائياً كل أحجام الأيقونة المطلوبة لأندرويد من صورتك ويضعها
في `android/app/src/main/res/mipmap-*/launcher_icon.png`، وهي نفس الأيقونة
المحددة في `AndroidManifest.xml` (`android:icon="@mipmap/launcher_icon"`).

### 5. ربط Supabase
أنشئ مشروعاً على https://supabase.com (مجاني)، ثم:
1. افتح SQL Editor ونفّذ كامل محتوى `supabase/schema.sql` الموجود هنا —
   سينشئ كل الجداول الثمانية، الفهارس، العلاقات، RLS، ودوال التحقق من كلمة مرور الأدمن.
2. من Project Settings → API، انسخ `Project URL` و `anon public key`.
3. افتح `lib/services/supabase_service.dart` وضع القيمتين في `SupabaseConfig`.

كلمة مرور الأدمن الافتراضية هي **AaSsDd2006** (مخزّنة كـ SHA-256 hash في
قاعدة البيانات فقط، وليست نصاً مكشوفاً في الكود أو الـ APK). غيّرها فوراً
من داخل لوحة الأدمن بعد أول تسجيل دخول.

### 6. تشغيل التطبيق أثناء التطوير
```bash
flutter pub get
flutter run
```

### 7. بناء الـ APK النهائي
```bash
flutter build apk --release
```
الملف الناتج: `build/app/outputs/flutter-apk/app-release.apk`

## ما الذي يعمل فعلاً في هذا المصدر
- حفظ محلي كامل (SQLite) لكل المباريات واللاعبين — يعمل بدون إنترنت 100%.
- مزامنة تلقائية مع Supabase عند عودة الاتصال (بدون تكرار أو فقدان بيانات).
- حسابات الورق (نقاط، طرّقات بقيمة 25 افتراضياً، فارق النقاط والطرّقات، تراجع).
- حسابات الدومينو (نقاط فوز 101 افتراضياً قابلة للتعديل، نقاط متبقية، إعلان فوز تلقائي).
- سجل مباريات مع فلترة وبحث وحذف.
- لوحة متصدرين (عام + ورق + دومينو) مع ميداليات 🥇🥈🥉 ونسبة فوز.
- لوحة أدمن محمية بكلمة مرور عبر Supabase RPC (إعلانات، تحديثات، نصوص،
  إعدادات الألعاب، رسائل، وضع صيانة، تغيير كلمة المرور) — فقط الوظائف الثماني المطلوبة، بدون إحصائيات زائدة.
- تصميم Dark Mode كامل بالألوان المطلوبة (أسود/ذهبي/أخضر/أحمر) ودعم RTL.

## محدودية يجب معرفتها
- صور بطاقتَي "دومينو" و"ورق" في الصفحة الرئيسية تستخدم حالياً أيقونات
  Material بدل صور فوتوغرافية احترافية (لم أُزوَّد بصور منفصلة للدومينو/الورق،
  فقط أيقونة التطبيق). يمكنك إضافة صورك الخاصة بسهولة — راجع قسم "إدارة الصور"
  داخل لوحة الأدمن في التطبيق للتفاصيل.
- ميزة "إدارة الصور" في لوحة الأدمن حالياً نص إرشادي فقط (لم تُربط برفع فعلي
  إلى Supabase Storage) — يمكن تطويرها لاحقاً بسهولة.
- RLS الحالي يسمح بالكتابة العامة على matches/players (لا يوجد تسجيل دخول
  للمستخدم العادي حسب طلبك)، وهذا مقبول لتطبيق تسجيل نتائج محلي بين أصدقاء،
  لكن لو أردت حماية أقوى من التلاعب لاحقاً يمكن إضافة Supabase Auth للمستخدمين.
